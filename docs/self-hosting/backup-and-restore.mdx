---
title: "Backup and restore"
description: "Protect PostgreSQL truth and the encryption key required for sealed credentials."
---

PostgreSQL is the durable source of truth for Organizations, Integrations, Alert Events, Incidents, Conversations, Investigations, Tool Runs, Findings, audit records, and Postmortems.

Back up PostgreSQL consistently and store the deployment encryption key in a separate protected system. A database backup without that key cannot recover sealed Integration credentials; the key without the database does not recover product records.

Rehearse restoration in an isolated deployment. Verify record counts, sign-in, Organization isolation, Integration credential access, and a new Investigation before declaring recovery complete.

Use a PostgreSQL-consistent backup method supported by your deployment, record its server
version and timestamp, and protect it as production data. Back up the active sealing key
through a separate custody path. Never place either artifact in this repository.

Restore into an isolated database with the matching key, start the same OpenCluster
release, and wait for `/readyz`. Verify one record from each critical Organization, open
one sealed Integration credential through **Verify**, and run a new cited Investigation.
Only then promote the recovery. A record-count match alone does not prove credentials or
Organization isolation survived.
