---
title: "Upgrade"
description: "Upgrade OpenCluster safely with backups, compatibility checks, and rollback limits."
---

Read the target release notes and changelog. Confirm the supported control-plane, frontend, Relay protocol, OpenAPI, image, and chart versions before changing production.

Back up PostgreSQL and retain the active encryption key. Apply one supported transition at a time, wait for migrations and readiness, then verify sign-in, Integration status, Relay compatibility, webhook delivery, and one Investigation.

Record the current image, chart, OpenAPI checksum, frontend version, and Relay version.
After the backup rehearsal, deploy the target release and wait for `/readyz`. Verify one
session, Organization selector, Integration, inbound test Alert Event, and cited
Investigation before reopening normal traffic.

Database migrations may make binary rollback unsafe. Use the release-specific rollback guidance and restore from a tested backup when required.

Do not skip versions or infer compatibility from matching image tags. A failed readiness
check, incompatible Relay, or unreadable sealed credential stops the upgrade. See
[Backup and restore](/self-hosting/backup-and-restore) and the target release notes.
