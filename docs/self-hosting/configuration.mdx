OpenCluster uses safe defaults for server addresses, local authentication, logs,
telemetry, investigation limits, concurrency, retention, retries, request timeouts, and
shutdown. A normal installation supplies database and encryption credentials plus its
public URL. Add AI credentials to enable Investigations. Supply the bootstrap credential
only for initial setup, then remove it.

OpenCluster resolves configuration in this order:

1. Built-in defaults.
2. The optional YAML file named by `OC_CONFIG_FILE`.
3. `OC_*` environment variables.

Environment variables override only the corresponding file values. Unknown YAML fields,
invalid values, and additional YAML documents stop startup instead of being ignored.

## Minimal configuration

```sh
export OC_DATABASE_DSN_FILE=/run/secrets/postgres_dsn
export OC_BOOTSTRAP_TOKEN_FILE=/run/secrets/bootstrap_token
export OC_ENCRYPTION_KEY_FILE=/run/secrets/sealing_key
export OC_PUBLIC_URL=http://localhost:8081
export OC_AI_PROVIDER=anthropic
export OC_AI_MODEL=claude-sonnet-5
export OC_AI_API_KEY_FILE=/run/secrets/model_key
controlplane
```

Direct alternatives are the same names without `_FILE`, for example `OC_AI_API_KEY`.
Use direct values for local development and mounted files for production when practical.
Never set both forms of one secret. Remove the bootstrap input after initial setup.

The standalone process does not automatically load `.env`. If using `.env.example`,
copy it to `.env`, fill in the file paths, and export its values before starting:

```sh
set -a
. ./.env
set +a
go run ./cmd/controlplane
```

Compose consumes `OPENCLUSTER_*` deployment inputs and supplies `OC_*` variables inside
the container. Use the [Quickstart exports](/getting-started/quickstart#1-create-local-secret-files)
for Compose rather than the standalone `.env.example`.

| Requirement | When needed |
| --- | --- |
| Database DSN and encryption key | A running HTTP service; retain the encryption key across restarts. Recovery commands need only the database DSN. |
| Bootstrap token | Initial Organization and Admin creation only. |
| AI provider, exact model, and API key | Together, to enable Investigations. Without them, the API remains available and Investigation requests report unavailability. |
| OIDC issuer, client ID, and client secret | Together, when using OIDC. Local authentication remains available. |
| GitHub App ID and private key | Together, when using GitHub App installation. |
| Slack App client ID and secret | Together, for Slack installation; signed inbound events also require the signing secret. |
| Relay listener and SPKI pins | When enabling Relay; use the deployment's separate Relay TLS settings. |
| Logs, telemetry, session lifetime, worker and model limits | Optional overrides with existing defaults. |

## Backend listener and public origin

The standalone backend listens on `:8081`; its local public origin is
`http://localhost:8081`. `OC_SERVER_ADDRESS` controls that backend listener.
`OC_PUBLIC_URL` is the actual public entry point used by browser requests, sign-in and
Integration callbacks, and generated webhook URLs. It is independent of the listen address.

For production, set `OC_PUBLIC_URL` to the reachable HTTPS origin served by your existing
edge routing. Browser origins may have one trailing slash; paths, credentials, queries,
fragments, and invalid hosts or ports are rejected. HTTP is allowed only for `localhost`,
`127.0.0.1`, and `[::1]` development origins. Session-cookie security is unchanged.
Use ASCII DNS names or canonical IP addresses; mapped and scoped IPv6 addresses are unsupported.

A separately installed frontend may listen on `http://localhost:8080`. Set that as the
public origin only after verifying its same-origin proxy to backend `8081` for `/api/`
(including SSE, authentication, and callbacks) and `/webhooks/`. This repository does
not supply that frontend or proxy. Without it, access the backend directly on `8081`.

## Configuration file

Set `OC_CONFIG_FILE` to load product-oriented YAML. Plaintext secrets are not accepted in
YAML; reference mounted files instead:

```yaml
server:
  address: ":8081"
  publicURL: "https://opencluster.example"
telemetry:
  logLevel: info
  otlpEndpoint: "otel-collector:4317"
database:
  dsnFile: /run/secrets/postgres_dsn
session:
  lifetime: 12h
relay:
  address: ":8443"
  spkiPins:
    - "BASE64_SHA256_PIN"
ai:
  provider: anthropic
  model: claude-sonnet-5
  apiKeyFile: /run/secrets/model_key
investigations:
  workers: 8
  maxPendingPerOrganization: 100
oidc:
  issuer: "https://id.example.com"
  clientID: opencluster
  clientSecretFile: /run/secrets/oidc_secret
slack:
  clientID: slack-client
  clientSecretFile: /run/secrets/slack_client_secret
  signingSecretFile: /run/secrets/slack_signing_secret
github:
  appID: "12345"
  privateKeyFile: /run/secrets/github_private_key
security:
  encryptionKeyFile: /run/secrets/encryption_key
  bootstrapTokenFile: /run/secrets/bootstrap_token
```

Omit optional sections that the deployment does not use. Values are strings except
`relay.spkiPins` (an array), `ai.maxOutputTokens`,
`investigations.workers`, and `investigations.maxPendingPerOrganization` (integers).
`session.lifetime` is a Go duration such as `12h`.

Relative secret paths in YAML are resolved from the configuration file's directory.
`_FILE` environment paths remain process-relative. An environment list setting such as
`OC_RELAY_SPKI_PINS` replaces the entire YAML list.

## Applying changes

Configuration and secret files are read once at startup. A file update does not reload
a running process. For Compose, recreate the control plane with
`docker compose -f deploy/compose/compose.yaml up -d --force-recreate control-plane`.
For Helm, ordinary values change the Deployment and trigger rollout. After updating an
existing Secret, run `kubectl rollout restart deployment/<release>-opencluster`, then
`kubectl rollout status deployment/<release>-opencluster`. Confirm `/readyz` and a bounded
Investigation before considering the change complete.

Set `OC_LOG_LEVEL` to `debug`, `info`, `warn`, or `error`; the default is `info`.
Use `OC_OTLP_ENDPOINT` when exporting traces to a collector.

Investigation execution exports one `investigation.run` span with child
`reasoning.complete` model-call spans. Existing Investigation metric names remain stable;
the historical duration outcome `needs_input` remains a metric dimension for requests
requiring narrower input, while the public lifecycle status is `concluded`. Tool metrics
group by the catalog Tool name across Integrations, without resource identifiers.
Local authentication is always available. OIDC is enabled when its issuer, client ID, and
client secret are all configured; a partial OIDC configuration stops startup. Relay is
optional and listens separately from HTTP;
customer Relays initiate outbound connections and pin the configured control-plane key.
`OC_SESSION_LIFETIME_SECONDS` is deployment-owned and defaults to 43,200 seconds.
Organizations start with 90 days of audit retention and can configure it independently;
browser credential lifetime remains deployment-owned.

## Model provider

OSS v0.1 supports deployment-level Anthropic or OpenRouter credentials. Set `OC_AI_PROVIDER`
to `anthropic` or `openrouter`, set `OC_AI_MODEL` to an exact model identifier accepted by that
provider, and set `OC_AI_API_KEY_FILE` to the mounted credential file. Organization-level
BYOK is not part of the OSS v0.1 contract.

For OpenRouter, use a full model identifier such as `z-ai/glm-4.7`. Requests require native
Tool calling and support for the supplied parameters. OpenCluster disables provider
fallbacks, denies data collection, requires zero data retention, and sorts eligible
endpoints by price. Account restrictions still apply. If no endpoint satisfies these
requirements, the Investigation fails; OpenCluster never relaxes them or selects another model.

Both providers default to an output allowance of 32,000 tokens per model request,
including reasoning. This allowance does not describe the model's context capacity.
Anthropic retains native thinking
continuation; OpenRouter retains the model's native reasoning continuation without adding
unsupported reasoning controls.

Anthropic thinking controls follow known model compatibility. Models requiring manual
thinking retain it during finalization; models that reject forced Tool selection use
automatic choice with the same structured-result validation. Unrecognized model IDs are
sent unchanged with provider defaults for optional thinking and effort controls. A model
that cannot satisfy the result contract fails clearly; OpenCluster does not replace it.

Token usage comes from provider responses. Missing or invalid categories are unavailable,
not measured zero. When a cache breakdown is missing or inconsistent, input can include
unsplit prompt usage rather than a measured uncached count. Reasoning is already included
in output usage. Stored totals sum available measurements and may be incomplete.

### Advanced: model budgets

Set `OC_AI_MAX_OUTPUT_SIZE` (YAML: `ai.maxOutputTokens`) to an output allowance supported
by the selected model, including reasoning. Its default is `32000` tokens.
Requests are sent directly; the provider determines whether the context fits. After an
actual context rejection, OpenCluster can retry once with optional context removed,
or with only finalization available when no optional context can be removed. Current
Messages and completed Tool exchanges remain intact. A rejected recovery fails the
Investigation rather than claiming an answer.

Provider retries share the configured request deadline, including time spent waiting.
Anthropic retry delays are respected without shortening them. An ambiguous connection failure
can cause repeated inference when the SDK retries; reported usage is not a complete billing ledger.

Restart the control plane, wait for `/readyz`, and run one bounded Investigation. Startup
proves that the file is readable; only a completed Investigation proves that the selected
provider and model satisfy the structured result contract. For authentication, quota,
rate-limit, or unsupported-model errors, correct the provider account or model and start
a new Investigation.

OpenCluster sends bounded Investigation context, Tool summaries, and the structured
result contract. It does not persist or expose model chain-of-thought. Review the
[security model](/security/overview) and the provider's retention, regional processing,
and training terms before production use.

| `OC_OIDC_CLIENT_ID` | OIDC client ID. |

| `OC_RELAY_ADDRESS` | Optional Relay gRPC listen address. |
| `OC_RELAY_SPKI_PINS` | Comma-separated control-plane SPKI pins. |
| `OC_AI_PROVIDER` | AI provider: `anthropic` or `openrouter`. |
| `OC_AI_MODEL` | Exact model identifier. |
| `OC_AI_API_KEY` / `OC_AI_API_KEY_FILE` | AI provider credential file. Direct value or file; do not set both. |

| `OC_INVESTIGATION_WORKERS` | Concurrent Investigation workers per replica; default `8`. |

| `OC_ENCRYPTION_KEY` / `OC_ENCRYPTION_KEY_FILE` | 32-byte credential-encryption key file. Direct value or file; do not set both. |

| `OC_OTLP_ENDPOINT` | Optional OTLP collector host and port. |
| `OC_SLACK_CLIENT_ID` | Deployment Slack App client ID. |
| `OC_SLACK_CLIENT_SECRET` / `OC_SLACK_CLIENT_SECRET_FILE` | Slack App client-secret file. Direct value or file; do not set both. |
| `OC_SLACK_SIGNING_SECRET` / `OC_SLACK_SIGNING_SECRET_FILE` | Slack request signing-secret file. Direct value or file; do not set both. |
| `OC_GITHUB_APP_ID` | Deployment GitHub App ID. |
| `OC_GITHUB_APP_PRIVATE_KEY` / `OC_GITHUB_APP_PRIVATE_KEY_FILE` | GitHub App private-key file. Direct value or file; do not set both. |

The OSS binary uses one mounted AI deployment for every Organization.

Back up retained installation data before replacing a pre-release deployment. This baseline
requires a fresh application database and does not import retained data from an older schema.

The shared HTTP server allows 10 seconds for headers, 30 seconds to read a request,
30 seconds to write a response, and 60 seconds for an idle connection. Restart after a
change, then verify `/healthz`, `/readyz`, sign-in, Organization access, Integration
verification, and one bounded Investigation.

## Webhook admission limits

Each control-plane process allows a shared burst of 600 webhook requests and restores
10 requests per second before authentication. This protects both alert and Slack intake;
changing an Integration identifier or forwarding header does not create fresh capacity.
During overload, alert webhooks receive `503` and Slack receives `429`; both include
`Retry-After`.

The budget is process-wide and multiplies across replicas. Integration identifiers and
credentials do not create separate in-memory quotas.

The metrics endpoint exposes `oc.webhooks.requests` by `surface` and bounded `result`,
`oc.webhooks.alert_events` for newly committed Alert Events, and
`oc.webhooks.slack_ack_duration` for Slack acknowledgement latency.

`OC_MAX_PENDING_INVESTIGATIONS_PER_ORGANIZATION` separately bounds the durable pending
Investigation queue; its default is `100`. Automatic alert Investigations, manual
Investigations, and Conversation turns share this Organization-wide capacity across
replicas. Claimed Investigations no longer consume pending capacity.

When a model provider is configured, an alert delivery that opens new Incidents must fit all their
automatic Investigations. If the current backlog cannot fit them, the whole delivery is
refused with `503` and `Retry-After`; a delivery needing more slots than the configured
limit receives permanent `400`. Without a model provider, alert intake records Incident state
without reserving Investigation capacity.
