title: "How investigations work"
description: "See how an incident becomes a bounded, adaptive investigation across connected systems."
---

An investigation starts either from an open incident or from a question you ask.
An incident turn combines the triggering alert with a bounded time window and the
connected sources available to that organization. A question turn carries your own words
and no alert, and many such questions have no cause to name — which revision is deployed,
what changed today — so their findings are recorded as observations rather than causes.

## Investigation flow

1. **Orient.** OpenCluster starts with the incident question, alert labels and
   annotations, timing, source links, and a current Kubernetes workload inventory when
   available.
2. **Select useful sources.** Verified integrations expose only the reads their granted
   access supports. OpenCluster chooses among them based on the incident; it does not
   query every integration by default.
3. **Follow the results.** Each result informs the next read. The path is adaptive,
   not a fixed checklist.
4. **Conclude.** OpenCluster records supported findings, unresolved leads, and practical
   next steps. Each finding cites the reads behind it.

## Access boundaries

Investigations can only use enabled integrations and verified access. Read windows are
bounded around the incident, repeated identical reads are suppressed, and truncated
results are marked. GitHub and Kubernetes source operations are read-only. Slack source
reads follow the connected credential, and an installed app may additionally reply only
in the thread where it was directly mentioned. Kubernetes investigations read live pod
and workload runtime, namespace events, and bounded container logs through the outbound
Relay, subject to its service-account and namespace restrictions.

Every read is clamped into the investigation's window, and a read that asks for a wider
one is narrowed rather than refused. The result states the window it actually covered, so
an empty answer reads as "nothing in this window" rather than "nothing exists". A question
asked outside any incident has no incident to bound it, so it looks back over the last 24
hours; attach the conversation to an incident when you need its window instead.

## When the cause is not established

OpenCluster does not turn an incomplete lead into a root cause. It may conclude with
unresolved leads or no findings. If a spend, read, turn, time, or progress limit stops
the work, the record identifies that limit and preserves the partial result.
