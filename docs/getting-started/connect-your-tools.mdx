Connect the systems your team already uses. Metrics show changes, logs describe application behavior, traces show request timing, and infrastructure and change history add context. OpenCluster can combine available sources during an Investigation.

## Choose an Integration

Browse the [Integration guides](/integrations/overview) for capabilities, provider permissions, and connection requirements. Start with one relevant source. You do not need an alert source to ask operational questions.

## Establish access

An Admin creates the Integration or authorizes the provider installation. GitHub and Slack use provider authorization. Kubernetes uses a Relay inside your environment. Alert senders need the webhook URL and secret configured at the sender.

The current deployment uses the [API setup procedure](/api-reference/overview#connect-an-integration). GitHub and Slack also require the documented advanced browser procedure until the frontend ships.

## Use the connected source

Prometheus, Loki, and Tempo check query access during creation. Provider authorization checks GitHub and Slack access. Kubernetes requires an explicit Relay capability check in the API procedure. Alert sources establish receipt when a valid delivery is accepted. Waiting for a first alert does not by itself indicate a failure.

A successful check confirms access at that time. Provider permissions, retention, and availability still affect later reads. Follow the source guide if access fails, then [ask a question or investigate an Incident](/getting-started/run-your-first-investigation).
