OpenCluster helps you understand workload health, errors, latency, deployments, and other operational questions. You can start a Conversation or investigate an Incident. An alert is not required.

## Prepare access

The current self-hosted deployment is API-only. A browser console is being developed. If you manage the deployment, follow [Docker Compose](/self-hosting/docker-compose) or [Helm](/self-hosting/helm). If OpenCluster is already running, use the [API authentication procedure](/api-reference/overview#authentication).

## Choose relevant sources

[Connect your tools](/getting-started/connect-your-tools) explains which sources can supply metrics, logs, traces, workload state, changes, and conversation context. Start with a source that can answer your question. Add an alert source if you want incoming alerts to create Incidents.

## Ask and follow up

Try “Why is checkout returning errors?” or “What changed in the checkout repository recently?” Include the service, namespace or repository, and relevant time interval.

[Run your first investigation](/getting-started/run-your-first-investigation) explains how to ask through a Conversation, investigate an Incident, review citations, and ask a follow-up question.
