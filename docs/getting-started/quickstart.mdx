Start with an operational question. You do not need an alert or an incident.

## 1. Prepare OpenCluster

For a new deployment, follow [Docker Compose setup](/self-hosting/docker-compose) or [Helm](/self-hosting/helm) and configure a model provider. If OpenCluster is already running, ask your administrator which sources are connected.

Administration currently uses the API. A web experience is under development. You can ask questions through an installed Slack app or the Conversation API.

## 2. Connect one relevant source

Choose a source from the [Integration overview](/integrations/overview). For example, Kubernetes can report the health of a named workload, while Loki can read application logs. An Admin connects the source using its guide and the linked API procedure.

## 3. Ask a specific question

Try “Is the checkout Deployment healthy in the payments namespace?” with Kubernetes, or “What errors appeared in checkout logs in the last 15 minutes?” with Loki. Include the workload, service, repository, or time interval you care about.

In a channel with the installed Slack app, mention `@OpenCluster` with your question. It replies in a thread. Alternatively, use the [Conversation API example](/api-reference/overview#ask-a-question), which covers sending a question and retrieving the answer. API questions require Editor or Admin access.

## 4. Review and follow up

Read the answer's findings, citations, and limitations. Missing evidence may leave a question unanswered. Ask a follow-up, such as “Did the deployment happen before the errors started?” In Slack, mention the app again in the same thread.

Continue with [Run your first investigation](/getting-started/run-your-first-investigation) for guidance on useful questions and reviewing results.
