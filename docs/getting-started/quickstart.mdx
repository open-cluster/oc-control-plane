This walkthrough starts the complete local stack, accepts a canonical Alert Event, and
opens the resulting Incident and Investigation. Allow about 15 minutes after the images
build.

## Before you start

You need Docker with Docker Compose, Git, a browser, port `8080`, and outbound HTTPS
access to Anthropic or Z.AI. You also need an API key and model identifier for that
provider. The checked-in Compose stack runs PostgreSQL, the control plane, and the
frontend; it does not publish the optional Relay unless you enable its profile.

The v0.1 repository does not declare minimum Docker, Compose, Git, CPU, or memory
versions. Before continuing, confirm `docker compose version` and `git --version` run.
Treat the absence of qualified minimums as a pre-release limitation, not permission to
assume an old deployment tool is supported.

OpenCluster v0.1 does not publish a qualified CPU or memory minimum. Docker must have
enough capacity to build the Go image and run three services; increase its allocation if
the build or PostgreSQL is terminated for memory pressure. Measure real Investigation
concurrency before sizing production.

## 1. Create local secret files

Clone the repository and create files outside version control for the PostgreSQL
password, PostgreSQL DSN, one-time bootstrap token, 32-byte encryption key, and model
provider credential. Each environment variable below names a file; it never contains
the credential itself.

On Linux or macOS, create the files and export the Compose inputs. Replace the obvious
placeholders; the password in the DSN must be URL-encoded and equal the PostgreSQL
password file.

```bash
install -d -m 700 .secrets
printf '%s' '<POSTGRES_PASSWORD>' > .secrets/postgres-password
printf '%s' 'postgresql://opencluster:<URL_ENCODED_PASSWORD>@postgres:5432/opencluster?sslmode=disable' > .secrets/postgres-dsn
openssl rand -hex 32 > .secrets/bootstrap-token
openssl rand -out .secrets/encryption-key 32
printf '%s' '<MODEL_API_KEY>' > .secrets/model-key
chmod 600 .secrets/*

export OPENCLUSTER_POSTGRES_PASSWORD_FILE="$PWD/.secrets/postgres-password"
export OPENCLUSTER_DATABASE_DSN_FILE="$PWD/.secrets/postgres-dsn"
export OPENCLUSTER_BOOTSTRAP_TOKEN_FILE="$PWD/.secrets/bootstrap-token"
export OPENCLUSTER_ENCRYPTION_KEY_FILE="$PWD/.secrets/encryption-key"
export OPENCLUSTER_AI_API_KEY_FILE="$PWD/.secrets/model-key"
export OPENCLUSTER_AI_PROVIDER=anthropic
export OPENCLUSTER_AI_MODEL='<MODEL_ID>'
export OPENCLUSTER_RUNTIME_UID="$(id -u)"
export OPENCLUSTER_RUNTIME_GID="$(id -g)"
```

Z.AI users set `OPENCLUSTER_AI_PROVIDER=zai` and a supported Z.AI model identifier.
Docker Desktop users without `id` can set both runtime values to an available numeric
non-root ID such as `1000`.

The DSN uses the Compose service host `postgres`, database and user `opencluster`. The
generated bootstrap token is longer than the 32-character minimum, and the encryption
key is exactly 32 bytes.

## 2. Start OpenCluster

From the repository root, export the required `OPENCLUSTER_*` values and run:

```bash
docker compose -f deploy/compose/compose.yaml up --build
```

Wait until PostgreSQL is healthy and the `control-plane` and `frontend` services remain
running:

```bash
docker compose -f deploy/compose/compose.yaml ps
curl --fail http://localhost:8080/healthz
curl --fail http://localhost:8080/readyz
```

The service table should show `postgres` as `healthy` and the other two services as
running. Both probe commands must exit successfully before you continue. Open
[http://localhost:8080](http://localhost:8080). If a service exits, run
`docker compose -f deploy/compose/compose.yaml logs <service>` and check the mounted file
paths before retrying.

## 3. Create the first User and Organization

Expand **Set up the first administrator**. Enter the bootstrap token, email, display
name, and password to create the first User. Bootstrap is deployment-wide and works only
once; it does not create an Organization.

Enter an Organization display name and submit the next step to create an Organization.
OpenCluster generates its canonical identifier and gives the first User an **Admin**
membership. The workspace opens with that Organization selected.

## 4. Connect a Generic Webhook

In **Integrations**, create a **Generic Webhook** named `Quickstart alerts`. Copy the
webhook URL and one-time secret immediately. Replace the placeholders below and send a
firing event:

```bash
curl --request POST "http://localhost:8080/webhooks/v1/integrations/<integration-id>/alert-events" \
  --header "Content-Type: application/json" \
  --header "X-OpenCluster-Token: <webhook-secret>" \
  --data '{
    "eventId":"quickstart-1",
    "status":"firing",
    "title":"Checkout latency is high",
    "severity":"critical",
    "startedAt":"2026-08-29T10:00:00Z",
    "deduplicationKey":"quickstart/checkout-latency",
    "labels":{"service":"checkout"},
    "annotations":{"summary":"Synthetic quickstart alert"}
  }'
```

The first valid delivery returns `202 Accepted`; an exact retry returns `200 OK`. A
`401` means the secret is missing or wrong. A `400` means the JSON does not match the
canonical schema. See [Generic Webhook](/integrations/alerting/generic_webhook) for all
fields and retry outcomes.

## 5. Verify the Incident and Investigation

Open **Incidents** and select the Incident created for `Checkout latency is high`. Start
an Investigation with a question such as “What evidence explains this alert?”

Progress moves from `queued` to `investigating`. A completed run ends as `concluded` or
`partial` and separates impact, Findings, hypotheses, Action Proposals, and limitations.
With only a synthetic alert, an inconclusive answer is honest and expected: the result
should identify missing evidence rather than invent a cause. Every material claim must
cite a numbered Tool Run.

## Clean up

Stop the stack while retaining the PostgreSQL volume:

```bash
docker compose -f deploy/compose/compose.yaml down
```

Do not add `--volumes` unless you intend to erase the local database. Before a production
deployment, review [Configuration](/self-hosting/configuration),
[Backup and restore](/self-hosting/backup-and-restore), and the
[security overview](/security/overview).
