---
title: "Run your first investigation"
description: "Start an Investigation from an Incident or an operational question and review its cited result."
---

Open an Incident and select **Investigate**, or ask a question from a new Conversation. An Investigation is one bounded evidence-gathering turn.

Watch semantic progress while OpenCluster reads connected sources. A finished result contains a summary, impact assessment, Findings, hypotheses, Action Proposals, limitations, and numbered Tool Run citations.

Select **Cancel investigation** when the question is no longer useful. Cancellation is
best effort: in-flight reads are allowed to stop, the terminal status becomes
`cancelled`, and no later activity is accepted for that Investigation.

Verify each material Finding against its cited Tool Run. Treat `partial`, `needs_input`, and inconclusive results as explicit limits, not failures to hide. A follow-up Message creates a new Investigation in the same Conversation; completed work never resumes.

For example, ask whether a deployment preceded a latency alert. A useful result may cite
one GitHub deployment read and one Kubernetes event read, keep an alternative hypothesis
`unresolved`, and propose a human-approved rollback with a verification check. If GitHub
or Kubernetes is unavailable, the result should state that limitation instead of claiming
a cause.

`failed` means no valid conclusion was recorded. `partial` means a valid bounded result
was forced by a spend, Tool Run, reasoning-turn, wall-clock, stagnation, or context limit.
`needs_input` asks for essential human information. Resolve missing access or answer the
question with a new Message; never edit the completed Investigation.
