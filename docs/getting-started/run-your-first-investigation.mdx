title: "Run your first investigation"
description: "Ask a question, review cited findings, and continue the Conversation."
---

Use an operational question or an existing Incident as your starting point. Connect a [relevant source](/integrations/overview) and configure a model provider. Editors and Admins can ask through the API and open investigations. Slack questions use the installed app.

## Ask an operational question

Start a Conversation with a specific question, such as “Is the checkout Deployment healthy in the payments namespace?” or “What errors appeared in checkout logs in the last 15 minutes?” Name the source or service when several could apply.

Use [Open conversation](/api-reference/conversations/open-conversation), then [Append conversation message](/api-reference/conversations/append-conversation-message). Include a new UUID in `clientMessageId` and reuse it if you retry the same submission. Read the reply with [List conversation messages](/api-reference/conversations/list-conversation-messages). An installed [Slack app](/integrations/collaboration/slack) can also answer direct mentions in an authorized channel thread.

## Investigate an Incident

An accepted firing alert can open an Incident and automatically queue an Investigation when a model provider is available. Follow that Investigation rather than opening a duplicate. To investigate an existing Incident again, use the [Incident investigation procedure](/api-reference/investigations/open-investigation).

## Review the result

**Chat** answers an operational question directly and may use connected read Tools. It does not create a structured Investigation Conclusion.

**An Investigation** records a summary, cited Findings, limitations, and recommended next steps. Citations identify the Tool Runs supporting each Finding. Check their sources, timestamps, and whether the observations were incomplete. Editors and Admins can [inspect a cited observation](/concepts/investigations-and-conversations#inspect-a-cited-observation).

An Investigation may conclude that the cause is still unknown. Missing access or telemetry does not prove that an issue did not occur. Review and verify Action Proposals before making a production change.

## Continue the Conversation

Ask a focused follow-up, such as “Did the deployment happen before the errors started?” Web Chat replies to queued Messages in order. To request an independent report, use [Open investigation](/api-reference/investigations/open-investigation) and include the Conversation ID if you want to link it to the report.
