Every refusal in OpenCluster names its reason. This page maps the common symptoms to
what they actually mean.

## The process

| Symptom | Meaning |
| --- | --- |
| Exits at startup naming an `OC_` variable | The configuration cannot be served. The message names the variable and the rule; nothing starts degraded |
| Startup refuses: the catalog serves Slack and there is no sealing key | The build serves a credential-bearing integration type and the deployment cannot encrypt a credential. Configure `OC_SEALING_KEY_FILE`, or bind no operator surface |
| `readyz` 503 while `healthz` 200 | The required database placement is unreachable. Liveness ignores dependencies on purpose — do not restart your way out of a database outage |

## Integrations

| Symptom | Meaning |
| --- | --- |
| Create refused with a vendor reason (`invalid_auth`, "does not know installation …") | The live check failed: the pasted credential or installation id is wrong at the vendor. Nothing was saved |
| Create refused: "no sealing key" | The deployment cannot hold the credential; nothing was saved or silently dropped |
| Verify turns an integration `failed` or `degraded` | The far end's answer changed: revoked token, suspended installation, disconnected Relay, missing scopes. The note names it |
| "the stored credential could not be opened; paste it again" | The sealing key changed since the credential was stored. Re-paste the credential |
| Webhook deliveries answer 401 | Wrong or rotated secret, or the integration is disabled — a disabled one refuses rather than records |
| Deliveries answer 200 instead of 202 | A replay of a body already accepted; the source should stop retrying it. Nothing was written twice |
| Delete refused with "records depending on it" | Signals, incidents or investigations reference the integration. Disable instead; the record of what a source produced must survive |

## Investigations

| Symptom | Meaning |
| --- | --- |
| Opening refused: "no model provider" | The deployment has no `OC_MODEL_*` configuration; everything else still works |
| Opening refused: "already running its limit" | Four investigations are running on this process; wait for one to end |
| A clarifying question instead of an investigation | The question tied to zero or several open incidents. Answer the one question it asked |
| Ends `failed`: "the reasoning step could not run" | The model provider refused, timed out or is down; the reason says which |
| Ends `failed`: "cited a read that never ran" | The model produced an untraceable finding and it was refused rather than stored |
| Ends concluded with no findings | Honest: what was read established nothing. Read the runs — the record shows what was tried |
| Runs show `truncated` | The source held more than the read's bound; the content is real but not the whole. Narrow the window or the query |
| A run failed "not one of the tools the selected sources offer" | The model reached outside the offered capabilities; the read did not happen and the record says so |

## Relays

| Symptom | Meaning |
| --- | --- |
| Kubernetes verify: "relay is not connected" | The Relay holds no live session — its side of the wire, its logs |
| Verify degraded: "does not advertise: …" | The cluster's own RBAC or the Relay build lacks the capability; fix in the cluster |
| Session conflicts on the roster | Two Relays presented one identity — a possible credential theft. Clearing the mark destroys the finding, so only an Admin can, and it is audited |
