---
title: "Self-host OpenCluster"
description: "Run the OpenCluster control plane with PostgreSQL and expose only the listeners you need."
---

OpenCluster runs as one static control-plane binary backed by one PostgreSQL database.
Database migrations run at startup. Health, metrics, alert intake, and operator access
share one HTTP listener; Relay traffic uses a separate gRPC listener.

## Requirements

- Go 1.26.6 to build from source
- PostgreSQL reachable from the control plane
- a TLS-terminating proxy for any public intake or Relay listener
- a model-provider account if you want to run investigations

## Start the control plane

Build the binary:

```bash
CGO_ENABLED=0 go build -trimpath -o oc-controlplane ./cmd/controlplane
```

Write the PostgreSQL DSN to a secret file, then start a minimal instance:

```bash
umask 077
printf '%s' 'postgres://user:password@postgres:5432/opencluster?sslmode=require' \
  > /tmp/opencluster-dsn

cat > opencluster.yaml <<'YAML'
server:
  address: "0.0.0.0:8080"
database:
  dsn_file: "/tmp/opencluster-dsn"
YAML

./oc-controlplane --config opencluster.yaml
```

Check startup and readiness:

```bash
curl --fail http://127.0.0.1:8080/healthz
curl --fail http://127.0.0.1:8080/readyz
```

This minimal process exposes only health, readiness, and metrics. Configure the
[operator, intake, Relay, and investigation settings](/self-hosted/configuration) before
using the product workflow.

## Listener boundaries

| YAML setting | Purpose | Recommended exposure |
| --- | --- | --- |
| `server.address` | Health, metrics, operator API, browser sign-in, and alert webhooks | Behind TLS; restrict operator routes at the proxy |
| `server.operator_address` | Compatibility switch that enables operator routes; must equal `server.address` | Same HTTP listener |
| `server.intake_address` | Compatibility switch that enables intake routes; must equal `server.address` | Same HTTP listener |
| `relay.address` | Outbound Relay sessions | Publicly reachable from clusters, behind the pinned TLS endpoint |
