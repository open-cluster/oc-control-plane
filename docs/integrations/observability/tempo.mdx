title: "Tempo"

Connect Tempo to find slow or failed requests and inspect how time was spent across services.

## Connect

You need the OpenCluster **Admin** role and permission to search traces and retrieve them by ID. Use an approved HTTPS endpoint reachable from OpenCluster, including any proxy prefix and excluding the Tempo API path. See [network and credential requirements](/security/overview).

Use bearer or Basic authentication with a read-only token. Basic authentication also needs a username. Supply a tenant ID when required by your endpoint.

Use the [Tempo configuration example](/api-reference/overview#tempo-configuration) to connect through the API.

## After connection

Creation runs a bounded trace search. A valid empty response confirms search access. No separate verification call is needed after successful creation. Trace retrieval may need separate permission at your endpoint.

OpenCluster can search with TraceQL and retrieve spans for a specific trace ID. Search returns a bounded sample. Use retrieved spans and their parent-child relationships to inspect where an example request spent time. Sampling, retention, instrumentation gaps and result limits affect coverage. Tempo metrics and tag discovery are unavailable.

Trace retrieval uses time bounds as backend search hints. A retrieved trace can include spans outside those bounds or omit part of the trace.

For example, ask “Where did checkout requests spend time in the last 15 minutes?” An optional TraceQL selector is `{ resource.service.name = "checkout" }`. Use a service name recorded in your traces.

## Troubleshooting

- If verification fails, check the endpoint, TLS trust, credentials and tenant.
- If search succeeds but a trace cannot be retrieved, check trace-read permission, retention and the selected tenant.
- If results are incomplete, narrow the search interval or selector. Replace credentials through PATCH with the full configuration and new token.
