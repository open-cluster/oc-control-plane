Integrations either create incident context or make relevant data available during an
investigation. OpenCluster chooses useful sources as the investigation develops; a
connected system is not queried on every incident.

| Role | Integration | What it provides |
| --- | --- | --- |
| Alerting | [Prometheus Alertmanager](/integrations/alerting/alertmanager) | Firing and resolved alerts that create and update incidents |
| Infrastructure | [Kubernetes](/integrations/infrastructure/kubernetes) | A current workload inventory through an outbound Relay |
| Collaboration | [Slack](/integrations/collaboration/slack) | Read-only conversations visible to the connected token |
| Source control | [GitHub](/integrations/source-control/github) | Read-only repository, change, pull request, CI, file, and release data |

Connecting an integration requires **Admin**. Verification records what the granted
access supports. Investigations only receive capabilities that were verified.

## How an integration is connected

There are two ways, and which one you get is decided by the deployment, not by the vendor:

| | |
| --- | --- |
| **One-click** | You press Connect, approve on the vendor's own site, and come back connected. No credential is ever pasted into OpenCluster. |
| **Credential form** | You paste a token the vendor issued you. It is verified live before it is saved, stored encrypted, and never shown again. |

The integration catalog says which one applies, per type, for **this** deployment: each type
carries `supportsConnect`, and the types that do not carry a configuration schema describing
the fields to collect instead.

It is genuinely per-deployment. GitHub offers one-click only where the deployment has been
given an App to install with; the same GitHub on a self-hosted deployment without one offers
the credential form. So a console must read `supportsConnect` and must not assume a vendor
always has one or the other — that assumption is wrong in both directions today. Anything
built on it also breaks silently the day a vendor gains a connect flow, rather than simply
gaining the button.

See [Credentials and data access](/security/credentials-and-data-access) before granting
access.
