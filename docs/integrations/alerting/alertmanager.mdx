---
title: "Prometheus Alertmanager"
description: "Create and update Incidents from Alertmanager deliveries."
---

Connect Alertmanager to open Incidents from firing alerts and update them when alerts resolve. OpenCluster uses Alertmanager's grouping key and retains the alert details.

## Connect

You need the OpenCluster **Admin** role, HTTPS reachability from Alertmanager to OpenCluster and Alertmanager 0.28.0 or later for the custom header. Use the [API session and Origin setup](/api-reference/overview#authentication):

```bash
curl --fail-with-body --cookie "$OPENCLUSTER_COOKIE" \
  --header "Origin: $OPENCLUSTER_URL" --header 'Content-Type: application/json' \
  --data '{"type":"alertmanager","name":"Production alerts","configuration":{}}' \
  "$OPENCLUSTER_URL/api/v1/integrations"
```

Save `integration.id`, `integration.webhook.url` and the one-time `webhookSecret`. Add the receiver below with the returned URL and secret. Merge its child route into your existing routing tree:

```yaml
receivers:
  - name: opencluster
    webhook_configs:
      - url: "https://oc.example.com/webhooks/v1/integrations/<integration-id>/alert-events"
        send_resolved: true
        http_config:
          http_headers:
            X-OpenCluster-Token:
              secrets:
                - "<webhook-secret>"

route:
  routes:
    - receiver: opencluster
      continue: true
```

Validate and reload Alertmanager. Keep the secret in protected configuration. The token authenticates the sender, so use TLS to protect it and the delivery.

## Verify and use

Fire a test alert. Expect `202 Accepted` on the first delivery and `200 OK` on an exact retry. Call the [verification endpoint](/api-reference/overview#verify-an-integration) to see the last accepted delivery. Use `GET /api/v1/incidents` to find the Incident.

OpenCluster records labels, annotations, timing and generator URLs. A new Incident queues an Investigation if a model provider is configured. The Integration receives alerts and cannot query Alertmanager for live alerts or silences.

## Troubleshooting

- **No delivery.** Check the receiver route, Alertmanager logs and reachability.
- **401.** Confirm the Integration is enabled and replace a rotated secret immediately.
- **400 or 413.** Check that the version 4 webhook body is intact. Send no more than 2,048 alerts and stay within 1 MiB per request.
- **503.** Honor `Retry-After` when provided. Review [webhook admission limits](/self-hosting/configuration#webhook-admission-limits) if failures recur.
