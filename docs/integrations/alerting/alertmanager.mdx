---
title: "Prometheus Alertmanager"
description: "Create and update Incidents from Alertmanager deliveries."
---

Connect Alertmanager to open Incidents from firing alerts and update them when alerts resolve. OpenCluster uses Alertmanager's grouping key and retains the alert details.

## Connect

You need the OpenCluster **Admin** role, HTTPS reachability from Alertmanager to OpenCluster and Alertmanager 0.28.0 or later for the custom header. Create the Integration through the API.

Follow the [Alertmanager creation example](/api-reference/overview#alertmanager-creation).

Save the returned webhook URL and one-time secret. Add the receiver below with the returned URL and secret. Merge this receiver and child route into your existing configuration. Adjust matching and ordering for your alert policy. See [Alertmanager routing configuration](https://prometheus.io/docs/alerting/latest/configuration/#route) for the full routing options:

```yaml
receivers:
  - name: opencluster
    webhook_configs:
      - url: "https://oc.example.com/webhooks/v1/integrations/<integration-id>/alert-events"
        send_resolved: true
        http_config:
          http_headers:
            X-OpenCluster-Token:
              secrets:
                - "<webhook-secret>"

route:
  routes:
    - receiver: opencluster
      continue: true
```

Validate and reload Alertmanager. Keep the secret in protected configuration. The token authenticates the sender, so use TLS to protect it and the delivery.

## After connection

Fire a test alert. Expect `202 Accepted` on the first delivery and `200 OK` on an exact retry. An accepted delivery proves receipt at that time, without a separate verification request. Waiting for a first delivery is not necessarily a failure.

OpenCluster records labels, annotations, timing and generator URLs. A new Incident queues an Investigation if a model provider is configured. The Integration receives alerts and cannot query Alertmanager for live alerts or silences.

## Troubleshooting

- **No delivery.** Check the receiver route, Alertmanager logs and reachability.
- **401.** Confirm the Integration is not disconnected and replace a rotated secret immediately.
- **400 or 413.** Check that the version 4 webhook body is intact. Send no more than 2,048 alerts and stay within 1 MiB per request.
- **503.** Honor `Retry-After` when provided. Review [webhook admission limits](/self-hosting/configuration#webhook-admission-limits) if failures recur.
