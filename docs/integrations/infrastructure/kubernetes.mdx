---
title: "Kubernetes"
description: "Inspect workloads, namespace events, and container logs through Relay."
---

Connect Kubernetes to investigate workload health and recent changes without exposing your Kubernetes API to OpenCluster.

## Prerequisites

- The **Admin** role in OpenCluster.
- A Relay connected outbound to your deployment. Find its ID with `GET /api/v1/relays`.
- A Relay service account allowed to read the workloads, pods, namespace Events and pod logs you intend to inspect. Keep credentials inside the cluster. Grant only the necessary read permissions.

## Connect

Use the [API session and Origin setup](/api-reference/overview#authentication). Replace the Relay ID and namespace list:

```bash
curl --fail-with-body --cookie "$OPENCLUSTER_COOKIE" \
  --header "Origin: $OPENCLUSTER_URL" --header 'Content-Type: application/json' \
  --data '{
    "type": "kubernetes",
    "name": "Production cluster",
    "relayId": "<relay-id>",
    "configuration": {"namespaceAllowList": "checkout,payments"}
  }' "$OPENCLUSTER_URL/api/v1/integrations"
```

The comma-separated namespace list narrows Relay access. An empty list leaves the scope to the Relay's own policy and Kubernetes RBAC.

## Verify and use

Save `integration.id` and call the [verification endpoint](/api-reference/overview#verify-an-integration). Check Relay connectivity and `toolAvailability` for each read. An Investigation can inspect a named Deployment, StatefulSet or DaemonSet and its pods, list Events in one namespace, or read a named container's logs. Local Relay limits and Kubernetes retention can shorten results. OpenCluster does not read Secret data.

## Troubleshooting

- **Relay disconnected.** Check the Relay process, endpoint and outbound network path.
- **Read unavailable.** Check the Relay version and advertised capabilities, then verify again.
- **Namespace or access refused.** Check the Integration allowlist, Relay policy and service-account RBAC.
- **Incomplete output.** Narrow the workload, container or time interval.
