title: "API reference"
description: "Authenticate, address an Organization, and use OpenCluster's public HTTP endpoints."
---

OpenCluster serves JSON over a versioned HTTP API. Every Organization-owned request sends
one `X-OpenCluster-Organization` header and requires a Principal with current membership
and the stated role permission.

## Authentication

Use the deployment's browser session or an approved bearer credential:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $OPENCLUSTER_TOKEN" \
  -H "X-OpenCluster-Organization: local" \
  https://oc.example.com/api/v1/incidents
```

Responses containing Organization data use `Cache-Control: no-store`. Unknown records
and records belonging to another Organization both return `404`.

## Core resources

| Resource | Endpoints | Minimum role |
| --- | --- | --- |
| Integrations | `GET/POST /api/v1/integrations` | Viewer to read, Admin to create |
| Incidents | `GET /api/v1/incidents` | Viewer |
| Investigations | `GET/POST /api/v1/investigations` | Viewer to read, Editor to open |
| Conversations | `GET/POST /api/v1/conversations` | Viewer to read, Editor to write |
| Relays | `GET /api/v1/relays` | Viewer |
| Audit events | `GET /api/v1/audit-events` | Viewer |

Listings return `items`, an opaque `next` cursor, and any documented partial fields.
Pass the returned cursor unchanged.

## Integration catalog

`GET /api/v1/integration-types` returns the Integration Types shipped by this deployment.
Each entry includes its `capabilities`, configuration schema, write-only field names,
availability, Relay and webhook requirements, provider source link, and
`documentationSlug` for the matching OpenCluster setup guide.

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $OPENCLUSTER_TOKEN" \
  -H "X-OpenCluster-Organization: local" \
  https://oc.example.com/api/v1/integration-types
```

Render forms from `configurationSchema`; never request or display an existing value for a
field named in `secretFields`.

## Investigation result

`GET /api/v1/investigations/{investigation}` returns
the lifecycle status, conclusion status, summary, impact, cited findings, final
hypotheses, action proposals, limitations, spend, and
`humanConfirmationRequired`.

Use these related endpoints:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `.../{investigation}/activity` | Ordered progress and hypothesis-update events |
| `GET` | `.../{investigation}/sources` | Offered sources and numbered Tool Runs |
| `GET` | `.../{investigation}/hypotheses` | Latest running snapshot or final hypotheses |
| `POST` | `.../{investigation}/cancel` | Stop active work; Editor or Admin |

## Postmortems

Postmortem routes are under a resolved Incident:

| Method | Path suffix | Outcome |
| --- | --- | --- |
| `GET` | `/postmortem` | Read the current draft or reviewed document |
| `POST` | `/postmortem` | Generate the first draft |
| `POST` | `/postmortem/regenerate` | Replace it with a higher draft revision |
| `PATCH` | `/postmortem` | Apply explicit human corrections |
| `POST` | `/postmortem/review` | Mark the document reviewed |

The full prefix is
`/api/v1/incidents/{incident}`.
Generation accepts optional explicit impact, resolution, and retrospective notes.
Missing human facts remain `Needs human input.`

## Webhooks

Inbound integrations use `/webhooks/v1`, not the operator API. Alertmanager sends a
bounded request authenticated by its static `X-OpenCluster-Token`; it does not sign the
request body. Treat webhook secrets as write-only credentials; OpenCluster shows a newly
minted secret once.

See [Prometheus Alertmanager](/integrations/alerting/alertmanager) for the supported
payload and delivery responses.

Admins can inspect failed processing with
`GET /api/v1/webhook-deliveries?status=failed`. A failed delivery can be retried without
resending or re-authenticating the original request:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $OPENCLUSTER_TOKEN" \
  -H "X-OpenCluster-Organization: local" \
  "https://oc.example.com/api/v1/webhook-deliveries?status=failed"

curl --fail-with-body -X POST \
  -H "Authorization: Bearer $OPENCLUSTER_TOKEN" \
  -H "X-OpenCluster-Organization: local" \
  https://oc.example.com/api/v1/webhook-deliveries/00000000-0000-4000-8000-000000000001/replay
```

`POST /api/v1/webhook-deliveries/{delivery}/replay` is accepted only for a visible failed
delivery. Completed work remains complete and the replay is audited.
