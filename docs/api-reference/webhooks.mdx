---
title: "Webhooks"
description: "Send bounded Alert Events through provider-specific `/webhooks/v1` endpoints."
---

Webhook intake is separate from the product API. The canonical path is `/webhooks/v1/integrations/{integration}/alert-events`; the Integration selects the provider adapter.

`202 Accepted` means the delivery is durable. `200 OK` means the same delivery was already accepted. `400` and `401` are permanent; `413` exceeds the 1 MiB bound; `429` and `503` should be retried with backoff.

Alertmanager uses `X-OpenCluster-Token`, which authenticates the sender but does not sign the body. Provider identity and lifecycle phase make redelivery and resolution idempotent.

Authenticate before parsing and keep request bodies at or below 1 MiB. Retry `429` after
`Retry-After` and retry `503` with bounded backoff; do not retry a `400` or `401` unchanged.
An exact retry of an accepted lifecycle phase is safe and returns `200`.

Use [Generic Webhook](/integrations/alerting/generic_webhook) for its exact canonical
schema or [Prometheus Alertmanager](/integrations/alerting/alertmanager) for the version 4
provider payload and receiver configuration.
