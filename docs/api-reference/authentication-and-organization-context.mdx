---
title: "Authentication and organization context"
description: "Authenticate with an opaque browser session and select one authorized Organization."
---

Normal `/api/v1` product routes authenticate with the `__Host-oc_session` cookie. Local sign-in and generic OIDC issue this opaque, revocable server-side session. General bearer API tokens are not shipped in v0.1.

Organization-owned operations require exactly one `X-OpenCluster-Organization` header. The server validates its syntax, resolves current membership, and checks Permission before invoking product logic. Do not place an Organization identifier in both a body and header.

Unsafe cookie requests also require the exact configured `Origin`. Missing authentication returns `401`; authenticated callers without the required Permission receive `403`.

Bootstrap is the only product setup request that accepts its one-time file-backed
credential as an `Authorization: Bearer` value. It creates only the first User and session;
the authenticated caller then uses `POST /api/v1/organizations`. Webhook tokens remain on
their `/webhooks/v1` routes and are not product API credentials.

```http
GET /api/v1/incidents HTTP/1.1
Cookie: __Host-oc_session=<opaque-session>
X-OpenCluster-Organization: platform-team-a1b2c3d4
```

Never persist the session in a generated client log. Browser clients should use the same
origin and let the cookie jar manage the `HttpOnly`, `Secure` cookie.
