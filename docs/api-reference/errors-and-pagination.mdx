---
title: "Errors and pagination"
description: "Handle stable error responses and opaque pagination cursors safely."
---

JSON errors contain a safe `error` message and may include a stable refusal reason or required Permission. Use the response status and request identifier for diagnosis; do not parse prose to drive authorization logic.

Collection operations accept a bounded `limit` and an opaque `after` cursor. Pass `next` back unchanged. An empty `next` means the page is complete.

Treat `400` as a permanent request problem, `401` as missing or rejected authentication, `403` as insufficient Permission, `404` as unavailable or inaccessible, `409` as a state conflict, `429` as retryable throttling, and `503` as temporary unavailability.

```json
{
  "error": "organization not found"
}
```

Do not use `404` to infer whether a record exists in another Organization. Retry `429`
after `Retry-After` when present and retry `503` with bounded backoff. Do not retry `400`,
`401`, `403`, or `409` unchanged.
