---
title: "Understand findings and citations"
description: "Interpret conclusion status, findings, citations, hypotheses, and proposed actions."
---

A finding is a statement supported by one or more recorded reads. Use its type, confidence,
and citations together; none is sufficient alone.

## Finding types

| Type | Meaning |
| --- | --- |
| Cause | The condition that initiated the incident, including its causal mechanism. |
| Trigger | A deployment or edit that set the incident in motion. |
| Contributing factor | A condition that increased impact or allowed propagation. |
| Symptom | An observed effect, not an explanation. |
| Propagation | Downstream impact caused by the original failure. |
| Ruled-out explanation | A plausible cause that a relevant read excluded. |
| Unresolved | A plausible explanation that could not be verified, with the read needed to resolve it. |
| Observation | A cited fact with no causal role, such as the currently deployed revision. |

## Confidence

- `confirmed` means the cited reads establish the finding.
- `likely` means the finding is supported, but a plausible alternative remains.
- `possible` means it is one open explanation among several.

Confidence is not impact or priority. A severe symptom can be confirmed while its cause
remains possible.

## Citations and reads

Each citation points to a read recorded during the investigation. The record includes
the source, query scope, time window, outcome, references, and whether the result was
truncated. Failed reads remain visible because unavailable data can explain why a lead
stayed unresolved.

OpenCluster stores a summary and provenance for each read, not a permanent bulk copy of
all returned content. A finding that cites a read that did not run is rejected rather
than stored.

## Conclusion status

- `verified_cause` means a confirmed cited cause includes the mechanism that produced impact.
- `supported_explanation` means the evidence supports an explanation while a plausible alternative remains.
- `inconclusive` means the available evidence did not establish an explanation.
- `answer_only` is used for operator questions that have no incident cause to diagnose.

## No established cause

A valid conclusion can contain only unresolved findings or no findings. Use the recorded
reads to see what was checked, then connect the missing source or run the recommended
operator check. Do not interpret an empty conclusion as proof that nothing happened.

## Proposed actions

Each action states its type, rationale, risk, reversibility, approval requirement,
verification procedure, and supporting reads. Actions are never executed automatically;
mitigation, rollback, and permanent-fix proposals always require human approval.
